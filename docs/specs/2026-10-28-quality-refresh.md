# AdPopcorn compatible maintenance

Align root/example React with the installed RN 0.85.3 Fabric reconciler and refresh compatible dependencies, the pinned Yarn manager and selected Trunk tools.
Preserve the freshly integrated main's native SDK, API, Gradle/podspec/platform and asset inputs, including its independently merged SDK/security updates.
Hold Babel 7, TypeScript 6, Bob 0.41 and the RN 0.85.3 integration families; avoid runtime or native migrations.

## Acceptance

1. Root/example React and the actual installed renderer version match; mismatched-version controls fail.
2. The official vendored Yarn artifact has checked integrity and the explicit install policies survive a fresh BASE-lock trial and recursive compatible refresh.
3. CI-equivalent immutable install, lint, typecheck, configured Jest tests, library build and production audit pass or disclose a concrete pre-existing boundary.
4. OSV covers the resolved lock identities, no-patch exceptions are explicit, and actual native secret findings survive the bounded reader into Trunk.
5. Existing selected Trunk tools are current, Pinact 4.1.1 exposes lint/upgrade, and the full no-fix scan passes.
6. Reconcile affected existing documentation and complete calibrated local review before concern-based commits and publication approval.

## Runtime and publication limits

Every Trunk invocation uses --monitor=false and one-off repository daemons are shut down before owned scratch removal.
No device, native build, ad service integration, publishing, release workflow execution or Dependabot/ruleset modification is authorized by this maintenance implementation.
The pre-existing unsupported web release job is recorded separately; do not silently redesign its toolchain.

## Generated-file scanner exceptions

TruffleHog excludes the exact official `.yarn/releases/yarn-4.18.1.cjs` and generated `yarn.lock` files after local metadata triage found CLI help identifiers and lock checksum fragments.
Each is a whole-file exception that also skips unrelated future secret findings, not a value-level whitelist.
The CLI’s bytes are independently SHA-512 verified against its official package and checked by CI.
OSV continues to inspect the lock’s npm identities, but dependency scanning does not replace secret detection.
